# Winbox v1.5.21

Winbox is now positioned for what it has become: an isolated Windows
vulnerability-research platform for Kali and AI agents. Transparent execution
remains a core workflow, alongside hypervisor instrumentation, PDB-backed
memory and symbol research, driver/IPC testing, containment, detonation, and
bounded evidence collection through the CLI and 64-tool MCP control plane.

This release focuses on making that platform faster and more dependable for
long-running, AI-driven kernel and user-mode research.

## Faster process and symbol workflows

- Process enumeration now reads each `_EPROCESS` once and derives all public
  records from that coherent pass instead of repeating overlapping work.
- Single-PID consumers stop walking as soon as the requested PID/name is
  found instead of materializing the complete process list.
- Boot-scoped CR3 stabilization remains intact, while CLI, MCP, and debugger
  attach paths share the optimized lookup behavior.
- Live validation found PID 4 after one EPROCESS read and reduced warm
  single-process lookup latency to roughly one third of the previous path.

## Batched breakpoint evaluation

- Breakpoint predicates and action lists evaluate as one pure batch inside a
  single CR3 masquerade, including nested, data-dependent `poi()` chains.
- Register-only and short-circuited expressions avoid CR3 swaps entirely.
- Candidate retry reruns the side-effect-free batch under the alternate KPTI
  CR3; mixed mappings retain the established per-read fallback and counters.
- The firing vCPU is carried explicitly through evaluation instead of relying
  on possibly stale stop state.
- Action-trace files are initialized before breakpoint installation and
  truncated when daemon sessions reuse breakpoint IDs.

## Bounded, AI-sized action traces

- `kdbg_bp_trace` now seeks backward for ordinary tail requests instead of
  reading the complete JSONL file.
- Added inclusive `from_hit`/`limit` pagination, exact expression projection,
  numeric-aware value filtering, and error-only filtering.
- Added streaming summaries with exact match/error counts and numeric min/max,
  plus capped distinct values, top values, and representative hit IDs.
- Entry count, response bytes, expression count, distinct-value tracking, and
  displayed text are independently bounded and expose explicit truncation.
- Malformed JSON, oversized records, missing files, CRLF, block boundaries,
  and unterminated final lines fail safely without unbounded reads.

## Stronger CET safety gate

- The debugger preflight now queries effective user shadow-stack policy for
  every running process rather than trusting only the system default.
- Protected or otherwise unqueryable processes make the gate fail closed.
- Preparation hides the VM's `cet-ss` CPU feature as well as updating Windows
  mitigation policy, preventing a newly launched process from opting back in.
- The original CPU XML and Windows policy remain exactly recoverable through
  the mode-0600 preparation backup.

## Documentation and positioning

- Reframed the project, package metadata, CLI help, and MCP instructions around
  the complete vulnerability-research platform rather than only command
  execution.
- Updated the README's debugger signatures and behavior, removing stale
  `mode="auto"` guidance and documenting watchpoints, breakpoint actions,
  trace queries, step-over/out, decode modes, and current symbol-loading APIs.
- Expanded the architecture description to cover the QMP/RSP research plane
  and host-enforced containment/evidence plane.

## Validation

- Local release gate: **2,249 passed, 5 skipped, 139 live tests deselected**.
- Real Unix-socket integration coverage exercises batched predicate/actions
  and composed trace pagination/filtering/summary through the daemon protocol.
- Multiple live MCP passes traced real `ntdll!NtClose` activity, including
  144-hit and 114-hit distributions plus a distinct-value truncation case.
- Decimal/hex matching, expression projection, error-only filtering, cursor
  continuation, summary completeness flags, and over-limit rejection were
  verified against the live target.
- Every debugger cleanup left CET safe, the gdbstub stopped, the VM and guest
  agent healthy, and System event IDs 41/1001/6008 empty.

## Upgrade note

Fully restart any long-running `winbox mcp` process after upgrading so it
reloads the new tool schema and trace-query implementation.
