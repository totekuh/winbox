## MCP-only final checks

1. Confirm the fresh MCP catalog contains 64 tools, including
   `kdbg_cet_status`, `kdbg_prepare`, and `kdbg_restore_cet`.
2. Call `kdbg_cet_status`. Expected:
   `SAFE: UserShadowStack=OFF, StrictMode=OFF, active_processes=0,
   unqueryable_processes=0`. System OFF alone is not sufficient.
3. Call `kdbg_prepare(confirm=false)` and `kdbg_restore_cet(confirm=false)`.
   Both must refuse without changing the guest.
4. Call `kdbg_ps`; require more than ten processes and PID 4 `System`.
5. Call `kdbg_status` after `kdbg_ps`; it should report that the persistent
   reader owns the connected gdbstub, not that the stub is absent.
6. Call `kdbg_base_refresh` and `kdbg_lm`; require an aligned canonical kernel
   base and `ntoskrnl.exe` in the module list.
7. Find the current LSASS PID, call `kdbg_user_lm`, then read 64 bytes at the
   returned `lsass.exe` base with `kdbg_read_va`; the result must be 128 hex
   characters beginning with `4d5a`.
8. Run a small concurrent batch of `kdbg_ps`, `kdbg_lm`, `kdbg_user_lm`, and
   `kdbg_read_va`; all requests must complete because the broker serializes
   them.
9. Query System event ID 1001 since the latest boot and verify there are zero
   bugchecks.

## Important live-VM caveat

The original release check only inspected `Get-ProcessMitigation -System`.
Later validation proved that OFF is a default, not a guarantee: 34 running
processes still had effective user shadow stacks, and the known WRUSSQ crash
recurred in a session with zero breakpoint hits. Current winbox scans effective
per-process state with `GetProcessMitigationPolicy` and fails closed before GDB
opens if any process is active or cannot be queried.

Fresh deployments should call `kdbg_prepare(confirm=true)` and reboot. It saves
the exact raw Windows mitigation values and original libvirt CPU XML, then
hides the VM's `cet-ss` CPU feature so later processes cannot opt in. Do not
call `kdbg_restore_cet(confirm=true)` without the mode-0600
`kdbg-cet-backup.json`; restore reinstates both layers and also requires reboot.
