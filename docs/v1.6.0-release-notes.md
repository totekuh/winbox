# Winbox v1.6.0

Winbox 1.6.0 turns kdbg into a combined dynamic and static vulnerability-
research environment. A live debugger stop can now be resolved directly to
exact-build PyGhidra pseudocode, source lines can be mapped back to assembly,
and native/WoW64 call chains can be unwound across both sides of the execution
boundary. The release also makes long-running AI workflows more durable,
bounded, and explicit about the provenance of every result.

This is a feature release with 12 commits since v1.5.21, 11 new MCP tools, and
substantial debugger, decompiler, symbol, caching, and workflow hardening.

## Dockerized live PyGhidra decompilation

- Added an independent headless Ghidra/PyGhidra service. The default Docker
  backend needs no host Java or Ghidra installation.
- Added `kdbg_decomp`, which accepts the current RIP, a runtime VA, a symbol,
  `module+RVA`, or a continuation cursor and returns focused pseudocode plus
  corresponding static assembly.
- Runtime and Ghidra load bases do not need to match. The bridge uses RVA as
  the stable coordinate across ASLR and validates PE machine, image size,
  timestamp, CodeView GUID+age, and immutable file SHA-256 before analysis.
- Added exact pseudocode-to-assembly provenance: exact, ranged, nearest
  forward/backward, ambiguous, and unmapped relationships are reported rather
  than pretending decompiler lines map one-to-one to instructions.
- Added batched source requests such as `lines="1-22"` with
  `assembly="mapped"`, bounded per-line instruction mappings, truncation
  metadata, and truthful handling of declarations and undecoded gaps.
- Added direct symbol and module/RVA queries, labelled call/branch targets,
  opaque stop-bound pagination cursors, and in-memory decompilation reuse for
  subsequent pages.
- Added compact, standard, and diagnostic evidence modes. Compact MCP output
  omits repeated runtime VAs and instruction bytes unless explicitly requested.
- Current live instruction bytes are compared with the exact static image and
  reported as match, mismatch, or not checked. Build identity and whole-runtime
  equality are never conflated.
- Verified PDB function publics enrich names and can recover missed function
  boundaries. Synthetic recovery provenance persists across project reopen and
  is never laundered into ordinary Ghidra analysis provenance.

## Independent and hardened Ghidra runtime

- Added `kdbg_ghidra_install`, `kdbg_ghidra_run`, and `kdbg_ghidra_stop`, plus
  matching CLI lifecycle commands.
- The image pins JDK 21, Ghidra, and PyGhidra inputs with checksums. It runs as
  the calling UID/GID with no network, a read-only root filesystem, all Linux
  capabilities dropped, and `no-new-privileges` enabled.
- The service exposes no TCP port. It uses a private mode-0600 Unix socket and
  keeps immutable binaries and durable analyzed projects under mode-0700 state.
- Worker API namespaces isolate sockets, locks, session files, logs, and
  containers so an older MCP process cannot downgrade or restart a newer
  worker—or destroy its in-flight work.
- Worker API 5 adds request IDs, half-open-client deadlines, active-operation
  status, timeout/cancellation reporting, and serialized Ghidra access.
- Docker defaults to a 4 GiB RAM ceiling, equal swap ceiling, two CPUs, a PID
  limit, bounded stop time, and rotating 10 MiB logs.
- Warm programs use a configurable one-to-four-entry LRU, defaulting to two.
  Durable projects are keyed by Ghidra version, immutable SHA-256, and analysis
  profile so analysis is normally paid once per exact build.
- Added `kdbg_decomp_status`, `kdbg_decomp_cache`, and dry-run-first
  `kdbg_decomp_cache_prune`. Inventory includes identity, size, age, profile,
  project state, and LRU order; unsafe live-project deletion is refused.

## Stop-pinned AI research workflows

- Added `kdbg_context`, a single bounded call returning registers, symbolized
  nearby assembly, architecture-correct stack words, metadata-driven
  backtrace, active breakpoints, and up to four selected memory reads.
- Added durable asynchronous continue jobs: `kdbg_cont_start` returns a token
  immediately, while `kdbg_cont_poll` and `kdbg_cont_cancel` survive MCP
  restarts and safely handle duplicate starts, stale workers, daemon changes,
  cancellation races, and bounded persisted results.
- Debugger state is now explicitly `running`, `halted`, or `indeterminate`.
  Random session IDs, monotonic stop IDs, resume-time invalidation, epoch-
  checked reads, atomic snapshots, and final revalidation prevent evidence
  from different stops being combined.
- Every `kdbg_*` MCP tool now returns the structured `winbox.mcp/1` envelope:
  `{schema, ok, result, error}`. Failures carry stable codes, retryability,
  operation names, bounded messages, and actionable recovery hints.
- Predicates now support exact-width `byte`, `word`, `dword`, and `qword`
  reads. Breakpoint actions additionally support bounded bytes, ASCII, and
  UTF-16 captures with per-expression, per-hit, per-trace, and action-count
  limits.
- Ghidra lifecycle/status JSON bypasses terminal wrapping and remains valid
  machine-readable JSON even at very narrow terminal widths.

## Exact artifact and symbol handling

- Attach now walks both native and WoW64 loaders before taking QEMU's single
  RSP connection and freezes every bounded image into an immutable,
  content-addressed manifest.
- Every staged PE is checked for architecture, live `SizeOfImage`, build
  identity, hash, and PDB identity. Matching PDB publics and x86 frame records
  are enriched automatically; manual per-DLL symbol preloading is no longer
  required.
- Same-name/different-build binaries publish atomically under build and SHA
  keys. Symbol records retain the exact PE path/hash and function metadata;
  concurrent or interrupted publication cannot expose a partial artifact.
- Guest-derived module paths now use inert UTF-16/base64 transport,
  `LiteralPath`, strict name validation, cache containment, random temporary
  names, mode-0600 atomic publication, and unconditional cleanup. Quote/NUL
  injection, traversal, symlink escape, and same-name races fail safely.

## Windows x64 and WoW64 unwinding

- Added Windows x64 metadata unwinding for PE32+ exception directories,
  `RUNTIME_FUNCTION`, unwind v1/v2 xdata, v2 epilogs, chained records,
  nonvolatile restores, frame registers, allocations, leaf functions, and
  machine frames.
- Unwind metadata comes from live pages when available. Windows-discarded
  `.pdata` may use only an exact identity/hash-verified staged PE; stack data
  always comes from the pinned live stop.
- Added real WoW64 detection through `_EPROCESS.WoW64Process`, native and x86
  PEB loader walks, architecture-labelled modules, and separate x86/x64 symbol
  stores for same-name DLLs.
- At an x86 stop, disassembly, stack display, step-over/out, backtrace, and
  context use 32-bit semantics. The conservative walker prefers exact-build
  PDB old-FPO/frame recipes, then validated EBP chains and bounded prologue
  simulation. Speculative stack hits remain separate candidates.
- Added exact-build native-x64-to-x86 transition stitching. kdbg derives the
  saved-context layout from the matching `wow64cpu.dll` instructions and PDB,
  validates the saved x86 context, and marks the explicit
  `wow64-x64-to-x86` boundary.
- Added the reverse arbitrary-x86-to-native-x64 stitch. Exact nt PDB layouts
  resolve the firing KPCR, current KTHREAD, and persisted native user trap
  frame; process identity, kernel-stack containment, TEB identity and bounds,
  x64 CS, exact `wow64cpu` RIP, native RSP, and the initial unwind must all
  agree before the `wow64-x86-to-x64` boundary is emitted.
- Both directions fail closed. Unrecognized builds, malformed metadata, or
  invalid contexts preserve the truthful single-architecture trace and expose
  `transition_error` instead of guessing.

## SMP, debugger, and edge-case hardening

- Removed silent vCPU fallbacks and made stop-thread parsing, `qC` resolution,
  selected-vCPU snapshots, breakpoint migration, and stepping explicitly SMP
  safe on four-vCPU guests.
- Hardware execution breakpoints are temporarily removed for the one
  instruction being stepped and then reinstalled, matching QEMU's pre-
  execution Z1 behavior without losing hit counts.
- Saved native WoW64 unwinding uses only the immutable attach manifest and
  never performs a kernel loader walk under compatibility-mode register state.
- PDB parsing, source mapping, cursor validation, cache selection, resource
  limits, stale stops, architecture ambiguity, corrupted loader lists, page
  boundaries, truncated functions, missing metadata, and hostile paths all
  received dedicated fail-closed edge coverage.

## Performance and live verification

- Reference Server 2025 Docker analysis took 48 seconds for native ntdll and
  623 seconds for the Windows kernel. Warm address queries returned in
  approximately 0.12–0.17 seconds, and concurrent requests serialized safely.
- Automatic SysWOW64 PING staging captured all 17 native/x86 loader entries,
  symbol-enriched all 17, copied 11.3 MiB, and reported no copy, symbol, or
  warning failures. The warm validated attach path took 11 seconds.
- Live x64 `.pdata` validation unwound kernel idle and user-mode services/RPC
  stacks. WoW64 validation covered x86 stepping, x86 hybrid unwinding, and
  both transition directions.
- The reloaded public MCP endpoints returned a repeatable complete 17-frame
  arbitrary-x86-to-native trace: nine x86 plus eight x64 frames, with the
  boundary at `wow64cpu!ReadWriteFileFault+0x31`. Bounded depth and
  `kdbg_context` returned the same stop-pinned transition evidence.
- Four-vCPU validation exercised accepted breakpoint hits on CPUs 2, 3, and 4
  and preserved the firing CPU across stepping and stop epochs.
- Final default suite: **2,544 passed, 5 skipped, 141 live tests deselected**.
  Dedicated real-daemon, QEMU RSP, Docker/PyGhidra, repeated-trace, concurrency,
  pagination, malformed-input, and resource-boundary coverage also passed.
- Final debugger detach resumed the VM; Windows 10.0.26100.1742 answered
  through qemu-ga and the gdbstub returned to its listening state.

## Upgrade notes

- Fully restart any long-running `winbox mcp` process after upgrading so it
  loads the 75-tool schema, worker API 5, structured envelopes, and new
  debugger protocol.
- Install the optional decompiler once with `winbox kdbg ghidra install`.
  Normal winbox execution and debugging do not require Docker or Ghidra.
- Existing Ghidra projects are preserved, but the versioned analysis profile
  can cause a one-time reanalysis for exact binaries first opened by v1.6.0.
- Scripts consuming old prose-form kdbg MCP failures must migrate to the
  structured `winbox.mcp/1` error object.
