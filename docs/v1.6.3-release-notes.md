# Winbox v1.6.3

Winbox 1.6.3 is a KDBG investigation-evidence and research-control-plane
release. It completes roadmap items **88–109**: bounded and verifiable thread
research, non-queueing snapshot/decomp admission, explicit completeness and
transport limits, exact-PDB execution evidence, immutable captures, and
operator-visible accounting. The MCP catalog grows from **80 to 92 tools**;
the exhaustive CLI manifest grows to **142 commands**.

## Thread research, attribution, and scheduler evidence

- Added bounded `kdbg_threads` detail profiles (`summary` and `full`), raw or
  named state/wait filters, deterministic sorting, and a `1..1024` output cap.
  Results distinguish a complete kernel walk from filtered or intentionally
  shortened output using `walk_complete`, `returned`, `filtered_out`, and
  `output_truncated`.
- Fixed human rendering so non-waiting threads display `—`, not a fabricated
  `unknown(<raw>)` wait reason. JSON continues to preserve raw scheduler data.
- Added opt-in `--resolve` / `resolve=true` thread-start enrichment. It returns
  the raw address alongside its kernel/user domain, loader module, RVA,
  architecture, and already-local nearest public symbol when proven. A loader
  miss remains `user_not_in_loader_module`; it is never relabelled as private,
  JIT, injected, or malicious without evidence.
- Added validated KPCR → KPRCB → CurrentThread evidence. Thread rows now show
  `running_on_vcpus`, and a bounded current-vCPU list includes foreign threads
  and explicit idle CPUs without claiming arbitrary-thread register state.
- Added opt-in exact-PDB wait-object evidence for displayed Waiting threads.
  It validates the embedded `KWAIT_BLOCK`, dispatcher type, and only follows a
  real `_KMUTANT.OwnerThread` relation. Unknown objects, stale IDs, external or
  multi-object waits, cycles, and depth limits are explicit partial evidence.
- Hardened ETHREAD list parsing: validates EPROCESS/Pcb, entry and head
  back-links, process ownership, CID, duplicate TIDs, and cap/cycle boundaries.
  A malformed list retains only its validated prefix and identifies the failing
  link/ETHREAD/stage.
- Added `--require-complete` / `require_complete=true` to thread and process
  triage paths. Partial evidence now raises retryable `incomplete_result` for
  strict callers, with structured `{stage, link, ethread, returned, reason}`
  detail rather than a misleading successful prefix.
- Added normalized additive thread presentation: FILETIME plus UTC time,
  unsigned NTSTATUS hex/name, null-aware pointers, and explicit
  `KTHREAD.KernelStack` semantics.
- Added named, complete host-side thread baselines and bounded diffs. They bind
  VM boot, PID/EPROCESS/CreateTime, and the nt symbol-store revision; cross-boot
  reuse or symbol drift is refused as `baseline_expired`.
- Added one-stop all-process `kdbg_thread_triage` ranking thread/runnable
  counts, newest rows, high context-switch samples, and conservatively scoped
  loader/module mismatches. Process, thread, sample, and result caps are all
  surfaced instead of silently presenting a subset as global truth.
- Added `kdbg_triage` as a bounded one-snapshot per-process view combining
  identity, thread summary, top context-switch rows, current-vCPU evidence,
  capped modules, and scoped start-address leads.

## Snapshot safety, admission, and decompilation control plane

- Added independent non-queueing operation leases for the RSP broker and
  decompiler worker. A concurrent request receives stable retryable `busy`
  evidence immediately; it does not disappear into a socket or JVM backlog.
- Snapshot results now include snapshot ID, reader owner/admission, queue delay
  (zero by design), stop duration, budget, and completion/error evidence.
  Doctor and decomp status expose active admission ownership.
- Enforced per-snapshot broker limits by default: 15 seconds, 16,384 reads, and
  16 MiB returned bytes. Idle client time counts. Limit expiry resumes Windows
  and returns retryable `snapshot_budget_exceeded` evidence.
- Added per-phase timing plus logical-versus-transport read/byte accounting.
  A bounded exact-range per-stop virtual cache is discarded before resume;
  cache fills consume real RSP budget while hits remain visible.
- Hardened exact-PDB and paging assumptions: malformed offsets/sizes/types,
  non-x64 stores, nonzero EPROCESS/Pcb, non-canonical VAs, and LA57 addresses
  are refused instead of decoded through stale x64 assumptions.
- `kdbg_decomp` now requires a verified warm exact Ghidra project by default.
  Cold analysis returns retryable `analysis_required` before it can hold the
  target stopped. `allow_cold=true` is the explicit escape hatch and reports
  the readiness/admission evidence.
- Expanded `kdbg_doctor` into a non-disruptive capability matrix for basic
  snapshots, thread research, interactive debugging, live decompilation, and
  offline preparation. It reports decomp backend/admission, next actions,
  source-versus-installed runtime provenance, catalog revision, capture
  inventory, and redacted operation telemetry without opening RSP.

## Investigation evidence and offline artifacts

- Added exact-PDB, x64-only `kdbg_vad` / `winbox kdbg vad` for bounded user VAD
  lookup or executable-map enumeration. It validates VAD tree links/ranges and
  returns inclusive bounds, protection, allocation kind, provenance, and an
  optional bounded MZ probe. Selected non-loader `--resolve` starts receive
  additive VAD evidence while retaining their original loader result.
- Added `kdbg_token`, `kdbg_object`, and `kdbg_handles`. They prove a process
  primary token, validated object header, and handle-table root from exact PDB
  data. Handle entry enumeration fails closed when a public PDB lacks the
  private `_HANDLE_TABLE_ENTRY` layout; no slot geometry is guessed.
- Added `kdbg_capture` for atomic, mode-0600 named process/system evidence
  artifacts captured in one bounded stop. Artifacts include boot/PDB identity,
  scope, completion boundaries, rendered/raw facts, VAD/token/handle evidence,
  phase timings, and read accounting.
- Added `kdbg_capture_diff` / `winbox kdbg capture diff` for bounded, purely
  offline comparison. It identity-gates matching captures by default and never
  opens RSP or reads target memory.
- Added a local 50-record metadata-only operation ring. It stores operation,
  timing, accounting, admission/busy outcome, and completeness only—never raw
  target memory, module paths, arguments, or error text. Doctor reports
  aggregate count plus p50/p95 and verbose recent records.

## MCP and CLI changes

- New MCP tools: `kdbg_doctor`, `kdbg_threads`, `kdbg_vad`, `kdbg_token`,
  `kdbg_handles`, `kdbg_object`, `kdbg_capture`, `kdbg_capture_diff`,
  `kdbg_thread_triage`, `kdbg_thread_baseline`, `kdbg_thread_diff`, and
  `kdbg_triage`. Existing process and decomp tools gained the bounded/strict,
  accounting, admission, and cold-analysis parameters described above.
- New CLI views include `kdbg vad`, `kdbg token`, `kdbg handles`, `kdbg object`,
  `kdbg capture`, `kdbg capture diff`, `kdbg thread-triage`,
  `kdbg thread-baseline`, `kdbg thread-diff`, `kdbg triage`, and enhanced
  `kdbg doctor --verbose` / `kdbg threads --resolve --wait-objects` controls.
- README and roadmap now document all 92 MCP tools, the 142-command CLI
  manifest, tool limits, exact-PDB gates, public-PDB handle limitation, and
  recoverable next actions.

## Verification and edge cases

- Added unit, broker, CLI, MCP, manifest, real-process, and live-VM coverage
  for malformed/cyclic VAD and ETHREAD trees, bad back-links, duplicate TIDs,
  partial and strict-result boundaries, noncanonical/LA57 addresses, layout
  drift, cache budget behavior, admission contention, corrupted captures,
  identity mismatches, telemetry redaction/retention, and public-PDB omissions.
- Current release verification: **734** CLI/MCP/coverage tests, **100** focused
  evidence/control-plane tests, and **2** live integration tests passed.
- Live Win11 checks exercised executable VAD/MZ evidence, a proven primary
  token and object header, fail-closed handle entry decoding, process and
  system captures, no-RSP offline diffs, selected thread resolution, and fresh
  MCP stdio registration. The VM was left running and responsive with the GDB
  stub stopped.

## Upgrade notes

- Fully restart long-running `winbox mcp` processes after upgrading so they
  load the twelve new tools and expanded schemas.
- Existing workflows remain conservative: unresolved starts remain leads,
  incomplete snapshots are visible (or rejectable in strict mode), and missing
  public-PDB private layouts remain explicit unsupported evidence.
- Capture artifacts are local, immutable, and mode 0600. Use normal filesystem
  retention/backup policy for evidence you intend to preserve.
