# Winbox v1.6.4

Winbox 1.6.4 closes roadmap items **110–112** with bounded VAD byte evidence,
offline exact-PE research leads, staged-relative breakpoints, and durable
detached breakpoint intents. The MCP catalog grows from **92 to 97 tools**;
the exhaustive CLI manifest grows from **142 to 147 commands**.

## Exact byte and static research evidence

- Added `kdbg_vad_extract` / `winbox kdbg vad-extract`. One bounded stop proves
  the selected process VAD and preserves up to 8 MiB through that process CR3
  as an immutable mode-0600 blob plus atomic JSON manifest. Responses contain
  hashes, holes, VAD/PDB/target identity, and snapshot accounting—never bytes.
  Strict mode publishes nothing when the selected range is incomplete.
- Added offline `kdbg_search` / `winbox kdbg search` over an exact symbol-store
  or persistent decomp-cache PE. It returns bounded ASCII/UTF-16 strings,
  exports, validated MSVC x64 RTTI vtable leads, and direct RIP-relative string
  references mapped through `.pdata` boundaries. An exact SHA-256 resolves
  deliberate same-name ambiguity and every artifact is rehashed before parse.
- Added opt-in `callers` / `callees` evidence to `kdbg_decomp`. Results include
  only direct relative calls proven by the exact cached PE; indirect calls,
  dynamic dispatch, tail jumps, imports, and guessed names remain non-results.

## Relative breakpoints and detached intents

- `kdbg_bp` now accepts case-insensitive `module+0xoffset` targets resolved only
  against the current attach's frozen staged manifest. Missing, ambiguous, and
  out-of-image targets fail before installation; `kdbg_bps` retains the
  canonical module-relative form.
- Added `kdbg_bp_intent_add`, `kdbg_bp_intents`, and
  `kdbg_bp_intent_remove`, with matching CLI commands. The mode-0600 atomic
  store retains only symbolic module+offset plus mode, condition, watchpoint,
  and action configuration—never a stale virtual address.
- Saved intents are inert by default. `kdbg_attach(apply_intents=true)` or
  `winbox kdbg attach --apply-intents` explicitly snapshots the store, stages a
  fresh manifest, then resolves and installs each intent inside the initial
  halted stop. Unresolved/ambiguous targets and installation failures are
  reported individually without guessing or aborting the valid session.
- README examples now document bounded breakpoint action traces and their
  automatic-continue behavior.

## Compatibility and verification

- Raised the optional MCP dependency floor to `mcp>=1.29.1,<2`; older allowed
  MCP builds fail tool registration under Python 3.14, while 1.29.1 is verified.
- Complete non-live suite: **2,895 passed, 155 live tests deselected**.
- Live Win11 verification searched the exact cached `ntdll` artifact for
  `NtClose`, installed and removed a staged `ntdll+RVA` breakpoint, exercised
  detached CLI and MCP intent storage, and installed that intent after a fresh
  explicit attach. The guest finished running and responsive with the gdbstub
  stopped and no retained test intent.
- VAD extraction was live-verified through CLI, MCP, and a fresh MCP stdio
  process with matching mode-0600 artifact hashes and clean teardown.

## Upgrade notes

- Fully restart long-running `winbox mcp` processes so they load the 97-tool
  catalog and new attach schema.
- Existing attaches do not apply saved intents. Opt in per attach; inspect the
  returned application report before continuing a target.
