# Winbox v1.6.1

Winbox 1.6.1 is a debugger and PyGhidra stability patch. It closes six
post-1.6.0 roadmap items: poison-safe detach, centralized debugger run-state
enforcement, truthful filtered-stop timeouts, serialized Ghidra cache/worker
maintenance, bounded debugger-child startup and reaping, and full CLI parity
for watchpoints, breakpoint actions, and trace queries.

## Debugger state safety and recovery

- Enforced one daemon operation matrix for `running`, `halted`,
  `indeterminate`, and CR3-poisoned sessions. Unsafe register, memory, write,
  breakpoint-mutation, stepping, and continue operations can no longer issue
  RSP traffic without a proven halt.
- Restricted an indeterminate session to status, interrupt recovery, and safe
  detach. Successful standalone interrupt recovery drains the RSP stop,
  captures a fresh stop generation, and only then restores normal operations.
- Removed the compatibility escape that allowed an unpinned memory read when
  no valid stop existed. Status now reports the operations allowed in the
  current state alongside `cr3_poisoned` and `resume_safe`.
- Fixed the deadline boundary after silently filtered stops. If time expires
  after an unrelated-CR3 hit, false predicate, or action auto-continue stop is
  received, the daemon records that already-observed stop and reports a
  truthful halted timeout instead of claiming the VM is still running.
- Made detach poison-safe end to end. Breakpoint cleanup runs before the daemon
  issues its resume-safety certificate, so a CR3 restore failure during cleanup
  cannot be hidden behind an earlier success response.
- CLI and MCP detach no longer perform an out-of-band resume unless the daemon
  exited and explicitly returned `resume_safe=true`. Poisoned or unknown state
  releases daemon ownership, leaves the VM untouched, and returns recovery
  guidance instead of guessing.

## Bounded debugger child lifecycle

- Added a shared startup supervisor for the interactive daemon and persistent
  reader. Startup status is newline-delimited, capped at 64 KiB, and bounded by
  absolute deadlines (60 seconds for the daemon and 30 seconds for the reader).
- Startup timeout, malformed/oversized status, EOF, explicit child failure,
  parent cancellation, and other exceptions terminate and synchronously reap
  exactly the owned child. The ownership check avoids signalling a reused PID.
- Successfully started long-lived children receive dedicated background
  `waitpid` reapers, preventing zombies in long-running CLI or MCP parents.
- Startup SIGTERM/SIGINT follows each child's safe cleanup path. Reader
  handshake failure and cancellation best-effort resume QEMU before closing a
  connection that may already have halted the guest.

## Serialized PyGhidra cache and worker maintenance

- Added one re-entrant, cross-thread and cross-process maintenance lock for the
  API-5 protocol family. Kernel `flock` ownership is authoritative, so stale
  lock-file contents do not block recovery and process death releases ownership
  automatically.
- The lock spans immutable input staging, automatic cache-budget enforcement,
  Docker/host worker startup, backend migration, every mutating worker
  transaction, worker shutdown, project import/open/save, and applied pruning.
- Applied prune now inventories, selects, checks worker ownership, and deletes
  within one transaction. It cannot race a worker start or an in-flight project
  operation. Dry-run inventory remains non-blocking and never carries a stale
  selection into a later apply.
- Concurrent worker starters recheck liveness under the shared lock. The
  existing pinned Ghidra 12.1.3 / PyGhidra 3.1.0 API-5 image remains compatible;
  no image rebuild or project migration is required.

## CLI breakpoint and trace parity

- Extended `winbox kdbg bp` with `--watch write|read|access`, validated
  `--size 1|2|4|8`, and repeatable `--action` expressions while preserving
  conditional execution-breakpoint behavior.
- Breakpoint creation and listing now identify watchpoint kind/width and action
  count. Watchpoint types and widths are shared with daemon validation to
  prevent frontend/backend drift.
- Added `winbox kdbg bp-trace BP_ID` with bounded tail and cursor paging,
  expression/value filters, errors-only selection, value summaries, top-value
  limits, continuation metadata, compact human output, and terminal-independent
  machine-safe JSON.
- Added the new command to the exhaustive CLI manifest with explicit live-test
  coverage classification.

## Tests and edge cases

- Added real-fork lifecycle tests for successful startup, explicit error,
  timeout, oversized status, parent `KeyboardInterrupt`, already-reaped/PID-
  reuse safety, process death, and repeated successful children without
  zombies.
- Added cache concurrency tests for worker-start versus prune and in-flight
  project transaction versus prune, plus nested acquisition, stale lock files,
  concurrent starters, and automatic lock release after process death.
- Added daemon tests for every run-state operation family, poison handling,
  interrupt recovery success/failure, cleanup-time CR3 poisoning, and the
  timeout boundary after unrelated-CR3, predicate-filtered, and action-filtered
  stops.
- Added CLI tests for exact watchpoint/action forwarding, every allowed and
  rejected width/bound, watchpoint rendering, all trace-query filters, compact
  output, and parseable JSON. Existing real JSON-line daemon-socket trace tests
  continue to cover the backend protocol.
- Complete default suite: **2,589 passed, 5 skipped, 141 live tests
  deselected**. Focused cache/process/socket/CLI suite: **740 passed, 1
  skipped**. `compileall`, `git diff --check`, and real Docker/PyGhidra
  integration also passed.

## Live verification

- Reloaded MCP reported the Docker API-5 worker responsive. Public dry-run
  pruning selected four candidates, removed zero, and left all four entries and
  387,050,786 bytes unchanged; the worker remained healthy afterward.
- An applied prune while five programs were held by the live worker correctly
  refused without deleting a binary or project.
- After explicitly preparing a CET-safe Server 2022 boot, the real daemon
  attached to `services.exe`, staged and symbol-enriched all 25 loader entries
  with zero failures or warnings, captured registers, and produced a complete
  five-frame Windows x64 pdata unwind.
- A durable continue entered running state, interrupt returned a truthful halt
  at stop ID 2, and detach certified `resume_safe=true` with
  `cr3_poisoned=false`. The daemon and continue-worker PIDs were reaped, the
  localhost gdbstub was stopped, and the VM and guest agent remained healthy.

## Upgrade notes

- Fully restart long-running `winbox mcp` processes after upgrading so they
  load the new detach behavior and debugger protocol implementation.
- No MCP tools were added or removed; the control plane remains at 75 tools.
- No PyGhidra image rebuild is needed. Existing API-5 containers and durable
  projects remain compatible.
- CET preparation is unchanged and remains an explicit, reversible operator
  choice. The validation VM was intentionally left CET-safe for subsequent
  debugger work.

## Complete v1.6.0 to v1.6.1 change set

- Roadmap items 71, 72, 73, 76, 77, and 78 completed with implementation,

- Roadmap items 79, 80, and 81 selected as the next implementation batch; no
  implementation of those future items is included in this release.
- Source changes cover the KDBG CLI, daemon, protocol, persistent reader,
  child lifecycle, MCP detach wrapper, PyGhidra client/cache/Docker lifecycle,
  and cross-process locking.
- Test changes cover CLI/MCP behavior, daemon state and interrupts, reader
  startup, child processes, PyGhidra hardening, real daemon socket behavior,
  and exhaustive command-manifest accounting.
